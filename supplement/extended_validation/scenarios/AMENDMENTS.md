# Pre-formal amendments, 2026-11-09

No formal results had been generated when the following clarifications were made.

1. The primary energy-weight comparison is pre-fixed at weight=1, using **actual weighted cost** = actual makespan / initial all-local serial time + weight * actual system incremental dynamic energy / initial all-local compute energy. All five weights are reported. The six-comparison Holm family consists of two opponents (PSO, HEFT-List) for static makespan, dynamic mean response time, and energy weight=1 actual weighted cost. Energy-aware methods are not ranked solely by makespan. Pareto plots and other weights are descriptive.
2. Aggregate link dynamic power 2W includes both endpoints, allocated 1W per active endpoint; the reported device-side energy includes local compute and its share of network energy, while total system energy additionally includes server compute and server network shares. Idle/baseline power is excluded. Simulated decision time excludes optimizer execution; actual planning wall time is logged separately. No real-time deadline or measured electrical-energy claim is made.
3. The initial unit test expected 1.5J in a hand calculation but κ=5e-28 gives 0.5W at 1GHz and 0.0625W at 0.5GHz, hence 2*0.5+4*0.0625=1.25J. The test expectation was corrected; simulator arithmetic was unchanged. The original failed test report is preserved as tests_initial.txt. No formal campaign was launched before the correction.
4. k=4, m=5, lambda=1.3 are read directly from the existing five_experiments.json; PSO parameters are a predeclared new-scenario setting, not a claim of re-tuning or identity with an archived best setting.

## After initial engineering pilot; before formal execution

5. Parent review found that forecast input transfers could begin before all parents completed, unlike actual dispatch. Both the forecast and greedy heuristic now wait for every parent before any input transfer. Forecast remains a non-insertion reservation surrogate; actual dispatch is work-conserving and can skip temporarily unavailable tasks. This difference is explicit and common to all methods, and all reported performance comes from actual event dispatch.
6. The initial pilot divided the budget by the number of future events. Although events were not passed to the planner, the allocation itself was an information channel. Formal allocation instead uses a fixed predeclared seven decision slots for every dynamic scenario, independent of the actual future event list: 1,000 calls divide as six slots of 143 and one of 142. Two-user instances have six observed epochs and hence 858 calls; three-user instances have seven and hence 1,000, unless all tasks finish earlier. Static and energy groups have one public planning slot of 1,000. Unused slots are reported and never redistributed using future knowledge. A test deletes an unobserved future event and changes unreleased job contents, requiring exactly equal initial observations and plans.
7. Initial engineering pilot and its hashes remain in 20261109_scenarios_v1. A corrected engineering pilot is in 20261109_scenarios_v2. The all-parent forecast test was then strengthened to use initially unfinished parents with unequal work (which distinguishes the old optimistic forecast); final frozen pilot and all formal runs use 20261109_scenarios_v3. No formal data were produced in v1 or v2.
